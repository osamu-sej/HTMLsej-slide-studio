# HTML向けアクションをAIに設計させる次段階

## 現在できること

アニメーション ウィンドウの「全ページの動き・操作を削除」で、資料全体のアニメーション、既定の演出、画面切り替え、メディアの自動再生、図形のクリックリンク、クリックで開く詳細、深掘りへのリンク設定、HTML独自のホバー・説明・連続モーションを一度に消せる。スライド上の文字・図形・写真と深掘りページ自体は残る。Undo 1回で削除前の資料に戻る。

「AIにHTML演出を相談」は会話欄に依頼文を用意する。現行の会話AIは `timeline` を書けず、回答は演出案の文章に限る。全ページへの自動適用を約束しない。

## 自動設計を実装するときの条件

1. **資料を読む**：スライドの順番、見出し、本文、ノート、図表の意味、配置済み部品のID・種類・位置をAIに渡す。画像データのbase64や削除前の動きは渡さない。非表示スライドも取りこぼさず、発表時には引き続き非表示とする。
2. **構造化して返す**：ページ番号、対象ID、効果、開始条件、長さ、クリック先、演出意図をJSONで受ける。現行の `timeline` と図形 `action` の範囲に変換できない提案は文章のまま残し、勝手に別の効果へ置換しない。
3. **全ページを照合する**：長い資料は数ページ単位で生成し、全ページの応答が揃ったときだけ一つの案として提示する。IDが存在しない、効果が未対応、ページが欠けた、という場合は適用せず修正させる。
4. **確認して反映する**：ページごとのプレビューと変更一覧を表示し、一括またはページ単位で採用できるようにする。反映時は資料の文字・図形・画像・元マスターを変更せず、Undo 1回で戻せるようにする。
5. **実ブラウザで検証する**：クリック順、トリガー、詳細、移動先、HTML書き出し、非表示スライド、動きを減らすOS設定を確認する。

現在の通常会話は内容編集で手配置の `elements`・`timeline` を保護する設計なので、アクションの自動生成には専用のAPIと適用画面が必要。
